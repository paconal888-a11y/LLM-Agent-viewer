## 비교 후 반영한 개선

### 입력을 별도 화면에서 검사

상세 패널의 **모델 입력**은 선택한 단계까지 기록된 마지막 `model.request`를 표시합니다. 역할별 메시지, 도구 schema와 생성 설정을 조회할 수 있습니다. 다음 모델 요청으로 이동하면 같은 에이전트·요청 유형의 이전 입력과 비교합니다.

- messages 배열 위치별 유지·추가·제거·변경
- 도구 이름별 schema 변경
- 주·하위 에이전트와 대화 요약·일반 답변의 분리
- 입력 확정 전 상태와 진단 미수집 상태의 구분

저장된 이후 이벤트의 토큰 수를 이전 단계에 표시하지 않습니다. 입력을 조회하는 기능이며 임의 체크포인트에서 실행을 재개하는 기능은 아닙니다.

### 파일 원문과 모델 입력 연결

`file.decode`에서 **모델 입력에서 확인**을 누르면 같은 문자열을 포함한 후속 요청으로 이동합니다. 메시지에서 값이 일치하는 파일 읽기·규칙 조립·도구 결과 기록으로 돌아갈 수도 있습니다.

이 연결은 기록된 문자열·메시지 값의 일치를 확인합니다. 파일을 읽었으므로 반드시 모델이 그 내용을 따랐다고 판정하지 않습니다. 아직 후속 요청이 수집되지 않았다면 연결을 만들지 않습니다.

### 수치의 출처 구분

이벤트에 출처를 표시합니다.

| 표시 | 의미 |
| --- | --- |
| Python 계측 | 생성 루프·hook에서 수집한 연산 값. 텐서는 선택한 표본 |
| 입력 진단 | 템플릿·tokenizer 진단 결과 |
| 실행기 보고 | 실행기가 반환한 설정·캐시·사용량 |
| 하네스 변환 | 메시지 조립이나 스트림 복원 결과 |
| 파일 I/O / 연결 기록 | 파일 작업 또는 프로토콜 설정·왕복 |
| 미수집 | 실행기가 해당 값을 제공하지 않음 |

모델 입력 화면의 **진단 토큰**과 **보고 토큰**도 별도로 표시합니다. 생성 응답이 아직 없다면 보고 토큰을 추정하지 않습니다. 수집한 대조 결과가 있을 때만 일치·불일치를 표시합니다.

### 미검증 답변의 반복 중단

OpenHands SDK의 반복 감지를 참고해 더 좁은 조건의 검사를 추가했습니다. 미충족 조건이 남았을 때 **응답 객체·미충족 조건·도구 호출 수가 같은 상태**를 연속으로 세 번 만나면 실패로 중단합니다. `validation.repeat`에 반복 횟수, 중단 기준, 응답 이벤트 번호와 비교 해시를 기록합니다. 새 도구 호출이나 다른 응답이 있으면 연속 횟수를 다시 셉니다.

로컬 Qwen3-4B에서 첫 모델 입력을 동일하게 맞춘 전후 실행을 확인했습니다.

| 항목 | 적용 전 | 적용 후 |
| --- | --- | --- |
| 모델 호출 | 8회 | 3회 |
| 누적 입력 토큰 | 9,736 | 2,721 |
| 누적 출력 토큰 | 160 | 60 |
| 도구 호출 | 0회 | 0회 |
| 최종 상태 | 호출 한도로 실패 | 동일 응답 반복으로 실패 |

두 기록은 **같은 답변을 8회 반복한 실패**, **반복 응답을 3회에서 중단** 예제에 포함했습니다. 이 사례는 실패한 재시도의 비용을 줄였다는 결과입니다. 작업 성공이나 모델의 학습을 보여주는 결과는 아닙니다. 의미가 비슷한 답변, 반복 도구 오류, 모든 정체 패턴을 탐지하는 범용 검사도 아닙니다.

### 동작과 기록의 정확성

메시지의 API role과 작성 주체를 분리하고, 하네스가 추가한 완료 조건·보완·점검·지적을 입력 화면에서 표시합니다. 해당 메시지를 추가한 이벤트로 이동할 수 있습니다. 이전 기록에 출처가 없으면 미기록으로 남깁니다.

편집 중 비동기 저장, 큰 활성 세션, RPC 지연 응답과 단계 정지, 중첩된 완료 값의 타입, 계획 모드의 외부 도구 권한, 실행 설정 비교도 함께 보강했습니다. 재현 조건과 검증 범위는 [테스트·측정 결과](REVIEW.md)에 있습니다.

## 남은 차이와 우선순위

| 항목 | 현재 상태 | 후속 작업 |
| --- | --- | --- |
| 임의 상태 편집·실행 분기 | 저장 기록 조회와 실행 제어 지원 | 체크포인트 복원, 도구 부작용 처리부터 설계 필요 |
| 범용 운영 관측 | 자체 실행 기록과 비교 실험 지원 | 외부 trace 형식 가져오기와 표준 연계 검토 |
| 연산의 시각적 설명 | 선택 레이어의 수치·shape·표본 제공 | 연산별 설명과 조작성을 사용자 테스트로 점검 |
| 학습 효과 | 실습과 기록 탐색 제공 | 처음 사용하는 개발자의 과제 수행 평가 필요 |

기능을 추가할 때는 아래 세 과제를 기준으로 탐색 동작을 점검합니다.

1. AGENTS.md의 한 문장이 어떤 system 메시지에 포함됐는지 찾고 읽기 이벤트로 돌아간다.
2. 계산 도구 실행 전후의 두 요청을 비교하고 assistant 도구 요청과 tool 결과의 추가를 설명한다.
3. 요약 요청과 일반 답변 요청을 구분하고 원문·요약·현재 입력이 서로 다른 데이터를 담는 사례를 찾는다.

과제 수행은 UI 점검 기준입니다. 학습 효과를 입증하려면 사용 전후에 새로운 과제를 주고 독립적으로 평가해야 합니다.
