# 구조

Agent Lens는 브라우저, Python 하네스, 로컬 모델 실행기로 구성됩니다. 하네스는 입력을 구성하고 모델 응답에 따라 도구를 실행합니다. 모델 실행기는 전달받은 메시지로 텍스트와 도구 요청을 생성합니다.

## 처리 흐름

1. 브라우저가 프롬프트와 실행 설정을 JSON으로 전송합니다.
2. HTTP 서버가 실행 상태와 작업 스레드를 만듭니다.
3. 하네스가 규칙·이력·스킬 목록을 읽고 역할별 `messages`와 도구 schema를 조립합니다.
4. 실행기가 대화 템플릿을 적용하고 토큰화한 뒤 모델을 계산합니다.
5. 하네스가 응답의 도구 이름·인자·권한·경로를 검사하고 등록된 함수를 호출합니다.
6. 반환값을 `tool` 메시지로 추가하고 모델을 다시 호출합니다.
7. 완료 조건을 확인한 뒤 답변과 대화를 저장하고 브라우저에 표시합니다.

파일 I/O, 입력 변환, 모델·도구 요청과 결과는 이벤트로 기록합니다. 기록에는 당시 데이터와 소스 스냅샷, Python 호출 스택이 포함됩니다. 코드를 나중에 수정해도 이전 기록의 소스는 유지됩니다.

## 하네스 구성

| 구성 | 구현 |
| --- | --- |
| 규칙 | AGENTS.md, 없으면 agent.md를 읽어 system 메시지에 포함 |
| 스킬 | 이름·설명 목록을 먼저 공개하고 `load_skill` 요청 시 본문 전달 |
| 커맨드 | `commands/*.md`의 `$ARGUMENTS`를 치환해 프롬프트 확장 |
| 대화 | 원문 JSONL 보관, 최근 대화 선택, 선택적 로컬 모델 요약 |
| 도구 | 파일 읽기·쓰기·검사, 검색, 계산, 계획 상태 관리 |
| 실행 검사 | 도구 schema, 인자, 경로와 공개 권한 검사 |
| 완료 검사 | 명시한 도구·인자를 성공 결과와 대조하고 누락 시 보완 요청 |
| 반복 중단 | 같은 미검증 응답·미충족 조건·도구 호출 수가 연속 3회 반복되면 실패 처리 |
| 모드 | 역할 지침, 도구 권한, 호출 예산, 하위 대화 구성 |
| MCP·LSP | 별도 프로세스와 JSON-RPC로 통신하고 결과를 도구 메시지로 변환 |

규칙과 스킬은 모델의 입력입니다. 실행 권한은 Python 정책 코드가 검사합니다. 완료 조건은 지정한 도구 결과를 대조하며 자유 프롬프트의 모든 의도를 자동 판정하지는 않습니다.

## 누가 무엇을 정하는가

에이전트의 동작은 일반 코드, 모델의 선택, 설정이 나눠서 정합니다. 무엇을 고치려면 그 결정이 어디에 있는지부터 알아야 합니다. 화면의 단계 상세에 같은 구분이 표시됩니다(`inspection.js`의 `decision`).

| 단계 | 코드가 정함 | 모델이 고름 | 바꾸는 곳 |
| --- | --- | --- | --- |
| 규칙 로딩 | AGENTS.md, 없으면 agent.md를 찾아 system 메시지에 넣음 | 지침을 따를지 | AGENTS.md, 규칙 스위치 |
| 스킬 | `skills/*/SKILL.md`를 찾아 이름·설명 목록을 입력에 넣음 | `load_skill`로 본문을 불러올지 | SKILL.md, 스킬 스위치 |
| 입력 조립 | 메시지 순서, 포함 범위, 공개할 도구 | 없음 | `context.py`, 각 스위치 |
| 응답 해석 | 답변과 도구 요청의 분기, 호출 예산 | 답할지 도구를 요청할지, 그 내용 | `agent_loop.py`, 에이전트 모드 |
| 도구 실행 | 공개 여부, 인자·경로 검사, 함수 실행 | 어떤 도구를 어떤 인자로 부를지 | `toolkit.py`, `policy.py`, 도구·쓰기 스위치 |
| 결과 전달 | 결과를 `tool` 메시지로 다음 입력에 추가 | 결과를 어떻게 쓸지 | `agent_loop.py` |
| 기억 | 저장, 최근 대화 선택, 요약 시점과 범위 | 요약 문장의 내용 | `harness.py`, `memory.json`, 스위치 |
| 위임 | 권한·예산·대화 격리·보고 수집 | 위임 여부와 작업 문구, 각 답변 | `agents.json`, 에이전트 모드 |
| 완료 판정 | 완료 조건·수정 파일 검사 | 참여하지 않음 | `policy.py`, 완료 조건 입력 |

실행 주체와 결정 주체는 다릅니다. 파일을 읽는 것은 파일 시스템이지만, 그 파일을 읽기로 한 것은 코드(규칙·스킬 목록의 자동 로딩)일 수도 모델(`read_file` 요청)일 수도 있습니다.

| `toolkit.py` | 도구 schema와 구현 함수 |
| `policy.py` | 인자·권한·경로·완료 조건 검사 |
| `context_memory.py` | 대화 원본, 요약 생성과 재사용 |
| `feedback.py` | 보완 메시지 저장과 선택적 재포함 |
| `orchestration.py` | 모드, 하위 실행, 계산 대기와 결과 수집 |
| `inference.py` | 실행기 호출, 템플릿·토큰 진단, 응답 조립 |
| `reference_engine.py` | Python 생성 루프와 텐서·KV 관찰 |
| `runtime.py` | 로컬 HTTP/SSE 클라이언트 |
| `integrations.py` / `stdio_rpc.py` | MCP·LSP 어댑터와 프로세스 통신 |
| `trace.py` | 이벤트, 소스 스냅샷과 단계 정지 |
| `project.py` | 편집·복원과 버전별 코드 로딩 |
| `diagnosis.py` | 기록으로 실패·완료의 근거를 층별로 정리 |

Python 소스는 `local_agent_lab/`, 화면은 `web/`, 규칙·스킬·예제는 `demo_workspace/`에 있습니다.

## 편집과 적용

화면에서 `files.py`, `context.py`, `toolkit.py`, `policy.py`, `inference.py`, `agent_loop.py`, `harness.py`를 편집할 수 있습니다. 저장한 버전을 다음 실행에 불러오며, 실행 중에는 저장을 차단합니다. 편집기는 구문 검사·변경 비교·충돌 검사·백업·직전 저장 복원을 제공합니다.

기반 코드와 새 Python 모듈은 외부 편집기로 수정하고 앱을 재시작합니다. 파일별 적용 조건과 도구 추가 예제는 [하네스 수정](EXTENDING.md)에 있습니다.

## 관측 범위

- 파일을 읽은 사실, 모델 입력에 포함한 사실, 모델이 지침을 따른 결과는 각각 확인합니다.
- Python 실행기는 토큰별 연산과 선택 레이어·head·위치의 텐서 표본을 기록합니다. llama.cpp는 서버 응답과 보고된 통계를 기록합니다.
- 코드 강조는 계측한 관찰 지점과 호출 프레임입니다. 모든 코드 줄을 추적하는 디버거는 아닙니다.
- attention과 K/V 값은 계산 표본입니다. 모델의 숨겨진 사고나 답변의 의미적 원인을 복원하지 않습니다.
- Python 실행기의 forward 시간은 세 값으로 기록합니다. `observed_forward_ms`는 hook(텐서 표본·이벤트 기록) 비용을 포함한 `model()` 벽시간에서 사용자 정지를 뺀 값, `observer_hook_ms`는 hook 본문에서 따로 잰 관찰 비용, `forward_ms_excluding_hooks`는 둘의 차이로 hook 밖 계산 시간의 추정값입니다. 순수 커널 시간의 측정은 아니며, 요청 합계(`prompt_ms`·`predicted_ms`)에도 같은 세 값을 둡니다. llama.cpp 경로의 시간은 서버가 보고한 값입니다. 하네스 정지와 외부 서버 계산 정지는 구분합니다.

검증 환경과 수치별 해석은 [테스트·측정 결과](REVIEW.md)를 참고하세요.
