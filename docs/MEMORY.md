# 대화 원본, 요약, 모델 입력

모델에 다시 전달할 데이터는 하네스가 고릅니다. 디스크에 저장된 대화가 모두 모델 입력에 들어가는 것은 아닙니다. 이 프로젝트는 선택 전후 데이터를 기록합니다.

| 파일 | 내용 | 읽거나 쓰는 시점 |
| --- | --- | --- |
| `.runs/conversations/<session>.jsonl` | 완료한 대화의 전체 messages | 완료 시 추가 저장, 요약을 켠 다음 요청에서 읽기 |
| `.runs/sessions/<session>.json` | 최근 두 대화, 답변 발췌, 지적 목록, 요약·요약 범위·파일 경로 | 요청 시작 시 읽기, 요약 체크포인트와 완료 시 저장 |
| `.runs/summaries/<session>/<run>.json` | 실제 모델 요약, 원문 실행 ID, 범위, 문자 수 | 유효한 요약을 받은 뒤 저장 |
| `.runs/traces/<run>.json` | 파일 I/O, 요청과 응답, 선택·요약 전후, 당시 코드 | 실행 기록 저장 |

세션 경로의 실제 이름은 화면과 `Harness.history_path()`에서 확인할 수 있습니다. 모델 가중치와 KV 캐시는 위 텍스트 파일과 별개입니다.

## 기본 경로

요약이 꺼져 있으면 최근 두 완료 대화와 직전 답변 발췌를 선택합니다. 완료한 원문은 계속 JSONL에 추가됩니다. 원문 저장과 모델 입력 선택은 서로 다른 정책입니다.

기존 버전에서 최근 대화만 보관한 세션을 열면 남아 있는 원문만 이관합니다. 이미 보관하지 않은 과거 대화는 복원할 수 없습니다. 이 경우 `memory.archive.bootstrap`에 범위를 기록합니다.

## 요약을 켠 경로

1. `context_memory.prepare()`가 `demo_workspace/memory.json`과 대화 원본을 읽습니다.
2. 아직 요약하지 않은 원문과 기존 요약의 **문자 수**를 기준과 비교합니다. 최근 한 대화는 기본적으로 원문으로 남깁니다.
3. 대상이 있으면 기존 요약과 오래된 원문 조각으로 별도 `model.request`를 만듭니다. `model_purpose=compaction`, 도구 없음, temperature 0입니다. 실제 로컬 모델을 호출하며 호출·사용량·계산 대기 비용에 합산합니다.
4. 빈 답변, 출력 한도로 잘린 요약, 도구 요청은 저장하지 않습니다. 유효한 요약을 파일과 세션 체크포인트에 저장합니다. 뒤의 일반 답변이 실패해도 이 체크포인트는 남습니다.
5. `build_context()`가 요약을 출처가 있는 참고용 user 메시지로 넣고, 최근 원문과 현재 요청을 잇습니다. 요약 텍스트를 system 권한으로 승격하지 않습니다.
6. 다음 요청은 저장한 요약과 아직 요약하지 않은 원문을 읽습니다. 기준 이하라면 요약 모델을 다시 호출하지 않습니다.

원문은 삭제하지 않습니다. 요약은 손실이 있을 수 있는 생성 결과입니다. 문자열이 남았다는 사실도 모델이 내용을 지킨다는 보증과는 다릅니다.

## 포함된 실제 예제

**대화 원문 → 모델 요약 → 다음 입력**을 선택하고 **대화 저장소**를 여세요. 공개 실습용 가상 프로젝트의 원문 2,488자가 73자로 요약됐습니다. `ORBIT-731`을 문자열 대조에 입력하면 원문·요약·실제 messages의 포함 여부를 봅니다. 원문 JSONL, 세션 JSON, 요약 파일과 당시 모델 입력도 열 수 있습니다.

이 실행은 요약 1회와 답변 1회, 합계 입력 2,226토큰·출력 81토큰을 사용했습니다. **저장한 요약을 다음 요청에서 재사용** 기록에서는 요약 생성 없이 답변 1회로 `ORBIT-731, 한국어, guide.md`를 반환했습니다. 이 사례에서 사실이 보존됐다는 결과이며 모든 요약의 정확성을 입증하지는 않습니다.

직접 실험하려면 새 대화에서 **이전 대화 요약**을 켜고 중요한 이름·숫자가 있는 긴 메모를 입력하세요. 후속 대화를 두 번 이상 이어가며 `memory.compaction.check/start/result`, 요약용 요청, `memory.summary.include`, 일반 답변용 요청을 대조합니다. 기준은 편집 가능한 `memory.json`에서 바꿉니다. 낮은 기준도 가장 최근 대화는 요약 대상으로 고르지 않습니다.

## 이 구현의 범위

완료한 대화를 **다음 사용자 요청 시작 전**에 요약합니다. 현재 도구 루프의 중간 컨텍스트 초과, 모든 실행기의 토큰 예산 자동 관리, 의미 보존 평가까지 구현한 것은 아닙니다. 문자 기준은 학습하기 쉬운 명시적 정책이며 정확한 토큰 한도와 다릅니다. 요청당 조각·출력·호출 예산과 원문 4 MiB 읽기 한도가 있습니다. 초과하면 원본을 보존하고 오류를 표시합니다.

요약 파일에는 생성한 텍스트와 원문 범위를 함께 저장합니다. **대화 저장소**에서 요약 전후의 내용과 다음 요청에 포함된 메시지를 비교할 수 있습니다.

## 활성 상태의 크기 제한

세션 JSON의 읽기·쓰기 예산은 UTF-8 512 KiB입니다. 최근 대화가 이 한도를 넘으면 오래된 turn부터 활성 상태에서 제외합니다. 단일 turn이 커도 중간 tool 메시지를 잘라 넣지 않고 turn 전체를 제외합니다. 원문 JSONL은 보존하며 `memory.save.state_budget`에 선택 결과를 기록합니다. 이는 모델 요약이나 재학습이 아닙니다.

이전 버전의 큰 세션은 최대 8 MiB까지 읽어 원문을 먼저 보존한 뒤 활성 상태를 복원합니다. 요약용 원본 archive 읽기 한도는 4 MiB이며, 이를 넘으면 새 대화를 시작하라는 오류를 반환합니다. 무제한 대화 저장소·자동 archive 분할은 지원하지 않습니다.
