# 실제 에이전트로 옮기기

Agent Lens의 하네스는 동작을 관찰하려고 직접 만든 교육용입니다. 사용 중인 코딩 에이전트의 구현과는 다릅니다. 여기서 본 구조가 그대로 맞는다고 가정하지 말고, 실제 도구에서 하나씩 확인하세요. 문서에 적힌 동작도 버전과 사내 설정에 따라 다를 수 있습니다.

이 문서의 확인 방법은 절차입니다. Agent Lens가 다른 에이전트를 자동으로 분석하는 기능은 없습니다.

## 무엇이 옮겨지는가

| 구분 | 내용 |
| --- | --- |
| 그대로 쓸 수 있음 | 층을 나눠 원인을 좁히는 순서, 모델 입력의 원문을 먼저 확인하는 습관, 한 번에 한 조건만 바꾸기, 반복 측정, 코드로 확인하는 완료 조건 |
| 도구마다 확인해야 함 | 지시 파일 탐색 순서와 우선순위, 스킬 로딩 시점, 대화 압축 규칙, 권한 모델, 하위 에이전트 구조 |
| 옮겨지지 않음 | 이 저장소의 이벤트 이름과 화면, 호출 예산 같은 구체적인 값, Qwen3에서 관측한 모델 행동 |

## 사용 중인 에이전트에서 확인할 질문

내부 코드를 볼 수 없어도 대부분 실험으로 확인할 수 있습니다. 핵심은 모델에 전달된 요청 원문을 얻는 것입니다. 도구의 디버그 로그가 없다면 모델 API 앞에 요청을 기록하는 로컬 프록시를 두는 방법이 있습니다(사내 정책을 먼저 확인하세요).

| 질문 | 확인 방법 |
| --- | --- |
| 모델에 실제로 무엇이 전달되는가 | 요청 원문의 messages·tools를 저장해 차례로 비교 |
| 지시 파일을 어디서 찾고 어떤 순서로 적용하는가 | 위치마다 구분되는 표식 문장을 넣고, 입력에 어떤 순서로 나타나는지 확인 |
| 스킬의 이름·설명과 본문은 언제 읽히는가 | 설명과 본문에 다른 표식을 넣고, 어느 요청부터 나타나는지 확인 |
| 도구 요청은 어떻게 검사되는가 | 잘못된 인자나 허용 범위 밖 경로를 요청하게 하고, 거부 메시지가 다음 입력에 어떻게 들어가는지 확인 |
| 긴 작업에서 무엇이 사라지는가 | 초반에 넣은 표식이 입력에서 사라지는 시점과, 요약으로 바뀐 형태를 확인 |
| 완료는 무엇으로 판정하는가 | 테스트가 실패하는 작업을 주고, ‘완료’ 주장을 무엇이 막는지 확인 |
| 무엇을 설정이나 플러그인으로 바꿀 수 있는가 | 설정을 하나씩 바꾸고 요청 원문의 차이를 비교 |

## 모델을 바꿀 수 없을 때 무엇을 고를까

먼저 층을 좁히고 수단을 고릅니다. 결정적으로 할 수 있는 일은 코드로 옮기고, 판단이 필요한 일만 모델에 남깁니다.

| 관측 | 먼저 볼 층 | 고를 수단 |
| --- | --- | --- |
| 지시가 입력에 없음 | 모델 입력 | 지시 파일 위치 수정, 컨텍스트 구성 |
| 지시가 입력에 있는데 반복해서 따르지 않음 | 모델의 선택 | 지시를 좁히고 예시 추가. 어기면 안 되는 규칙은 코드 검사로 이동 |
| 매번 같은 절차를 설명함 | 모델 입력 | 스킬. 절차가 결정적이면 일반 스크립트 |
| 계산·변환처럼 답이 정해진 일 | 도구·하네스 | 일반 스크립트나 커스텀 도구 |
| 외부 시스템의 데이터가 필요함 | 도구·하네스 | 커스텀 도구 또는 MCP |
| ‘끝났다’는 말을 믿을 수 없음 | 도구·하네스 | 테스트·빌드를 완료 조건으로 강제 |
| 긴 작업에서 앞 내용을 잊음 | 모델 입력 | 상태 파일에 기록하고 다시 읽기, 작업을 나누기 |
| 도구 오류·시간 초과가 반복됨 | 도구·하네스 | 도구 구현과 오류 메시지 개선 |
| 위 층이 모두 정상이고 반복해도 실패 | 모델의 선택 | 작업을 더 작게 나누기. 그래도 실패하면 이 모델의 능력 밖으로 판단 |

플러그인은 위 수단을 묶어 배포하는 방법입니다. 효과를 확인하기 전에 플러그인부터 만들지 마세요.

## 개선을 증명하는 방법

1. 실제 업무에서 과제 5~10개를 고릅니다. 데모용 예제만으로 재면 업무 개선을 말할 수 없습니다.
2. 과제마다 코드로 확인할 수 있는 통과 기준을 정합니다. 테스트 통과, 생성 파일의 값, 재현 스크립트 등입니다.
3. 수정 전 기준선을 측정합니다. 조건마다 3회 이상 반복합니다.
4. 한 조건만 바꾸고 같은 횟수로 다시 측정합니다.
5. 통과 수, 사람이 다시 지시한 횟수, 토큰, 시간, 실패 층을 기록합니다.

Agent Lens의 [반복 측정](LEARNING.md#13-고친-것이-실제로-나아졌는지-측정하기)은 이 절차를 작게 연습하는 곳입니다. 여기서 얻은 통과율이 다른 모델이나 다른 하네스로 옮겨 가지는 않습니다.
