# 에이전트 모드

모드에 따라 system 지침, 공개 도구, 호출 예산과 대화 구성이 달라집니다. 모든 모드는 같은 로컬 모델을 사용합니다.

| 모드 | 실제로 바뀌는 것 | 기록에서 확인할 것 |
| --- | --- | --- |
| 한 에이전트 | 한 messages 배열, 기본 최대 8회 모델 호출 | 모델 → 도구 → 결과를 넣고 재호출 |
| 계획만 | 계획 지침 추가, 쓰기 권한 해제, 계획 도구 공개 | 선택 때 쓰기=true여도 적용 후 false, write_file 미공개·실행 거부 |
| 집중 점검 | 같은 messages 유지, 최대 16회, 완료 조건 통과 후 추가 점검 한 번 | agent.review의 후보 답변과 실제 추가 user 메시지, 다음 model.request |
| 하위 에이전트 | delegate_tasks 공개, 모델이 정한 작업을 독립 Run으로 분리 | agent.delegate → spawn → 하위 파일/모델/도구 → join → 주 tool 메시지 → 주 모델 |

집중 점검은 모델의 내부 reasoning effort나 학습된 능력을 바꾸는 기능이 아닙니다. 호출을 늘렸다는 이유만으로 답변이 좋아진다고 판정하지 않습니다.

## 하위 대화의 경계

`demo_workspace/agents.json`에는 집중 모드 예산·점검 문장과 하위 역할의 설명·지침·도구 허용 목록이 있습니다. 화면에서 수정하고 다음 실행 때 실제 파일 읽기와 입력 변화를 확인할 수 있습니다.

기본 하위 역할은 Explore(자료 탐색)와 Oracle(검토)입니다. 주 모델이 `delegate_tasks(tasks_json=...)`를 실제 도구 호출로 생성합니다. 현재 인자 검증기는 스칼라만 지원하므로 작업 목록은 JSON **문자열**로 전달합니다. 하네스가 문자열을 파싱하고 등록한 역할·작업 수·길이를 검사합니다.

하위 작업은 최대 3개, 기본 동시 작업자는 2개, 각 하위 모델 호출은 최대 6회입니다. 한 주 실행에서 위임 도구는 한 번만 실행할 수 있고 재귀 위임은 공개하지 않습니다. 하위 대화에는 다음을 전달합니다.

- 원래 사용자 요청의 참고 사본과 해당 하위 작업.
- 하네스 기본 지침, 실제로 다시 읽은 프로젝트 규칙, 켜져 있다면 스킬 목록.
- 선택한 역할 지침과 해당 역할의 제한된 도구 schema.

주 세션의 이전 대화·지적 목록, 쓰기 권한, MCP/LSP 연결은 자동으로 상속하지 않습니다. 같은 작업 공간을 읽지만 하위 쓰기는 허용하지 않습니다. 모델과 가중치를 공유하는 것과 messages를 공유하는 것은 다른 사실입니다.

하위 결과는 상태·오류·답변 앞 2,400자·호출 수·토큰 사용량으로 주 에이전트의 tool 메시지에 들어갑니다. 전체 하위 기록은 별도로 보존하며, 주 대화의 일반 세션 기억에는 하위 대화를 통째로 넣지 않습니다. 잘린 답변은 표시하고 실패도 그대로 반환합니다.

## 병렬 작업과 모델 계산

Python 작업자 스레드는 함께 파일을 읽고 컨텍스트를 만들 수 있습니다. 이 구현에서는 같은 실행기의 캐시·hook·관측을 보호하기 위해 **실제 모델 계산은 공유 lock으로 한 번에 하나씩** 수행합니다. `agent.queue`는 대기 시작, `agent.compute.wait_ms`는 계산 차례를 얻기까지의 측정값입니다. 외부 서버의 병렬 처리 성능을 측정한 수치가 아닙니다.

주 기록에는 하위 이벤트의 agent_id·하위 이벤트 번호·하위 기준 시간과 주 실행의 관측 시간이 함께 남습니다. 구조도 위에서 에이전트를 선택하면 해당 대화의 마지막 기록으로 이동합니다. 전체 에이전트의 기록을 시각순으로 볼 수도 있습니다. 단계 정지는 전역 관찰 순서를 하나씩 진행하고, 중지는 하위 실행에도 전달합니다. 이미 시작한 외부 HTTP 계산의 즉시 취소까지 보장하지는 않습니다.

## 관련 구현

[공개 OpenCode](https://docs.opencode.ai/docs/agents/)는 직접 대화하는 primary agent와 호출되는 subagent를 구분합니다. [OmO의 OpenCode판 역할 자료](https://github.com/code-yeongyu/oh-my-openagent/blob/dev/packages/omo-opencode/src/agents/AGENTS.md)는 Sisyphus·Hephaestus·Explore·Oracle 같은 역할과 서로 다른 지침·도구 제한을 설명합니다.

Agent Lens는 역할별 지침·권한과 독립 대화 구성을 구현합니다. 제품별 모델 라우팅, ultrawork, Atlas 인계나 팀 프로토콜은 포함하지 않습니다.

## 실습

1. **구성 · 비교**에서 같은 요청을 한 에이전트/집중 점검으로 비교합니다. 점검 메시지의 추가, 호출·입력 토큰·시간 증가를 확인하세요.
2. 하위 에이전트 실습을 실행합니다. 주 모델이 만든 작업 문자열, 두 하위의 첫 model.request, join 뒤 주 모델의 다음 요청을 차례로 대조합니다.
3. agents.json의 역할 지침과 도구 목록 하나를 바꿔 다시 실행합니다. 파일이 바뀐 사실, 입력이 바뀐 사실, 행동이 바뀐 사실을 따로 확인하세요.
4. 왜 간단한 요청은 한 에이전트가 더 나을 수 있는지 설명해 보세요. 전체 토큰·결과 전달 손실·대기 비용·작업 분리의 이점을 근거로 판단합니다.
