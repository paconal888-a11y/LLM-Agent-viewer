## 자동 검증

```powershell
uv run --extra reference --extra integrations --offline python -m unittest discover -s tests -v
node --test tests/architecture.test.cjs tests/inspection.test.cjs tests/editor.test.cjs tests/settings.test.cjs tests/export_search.test.cjs
```

96개 Python 테스트를 실행합니다. 모의 모델로 도구 루프·권한·완료 조건·기억·편집·HTTP 경계를 검사합니다. 작은 무작위 Qwen 모델로 실제 KV 사용/전체 재계산의 결과와 접두부 처리를 검사합니다. MCP는 별도 stdio 프로세스를, LSP는 설치된 실제 pylsp의 진단·심볼·정의·문서 변경을 검사합니다. 모드 검증에는 독립 하위 컨텍스트·권한 제한·실제 결과 합류·대기 중 중지 전파·에이전트별 지적 연결을 포함합니다. 이 숫자는 다운로드한 모델이 모든 지시를 잘 따른다는 뜻이 아닙니다.

## 실제 모델과 화면 검증

최종 환경에서 96개 Python 테스트와 구조도·입력 검사 Node 테스트 18개가 통과했습니다. 공개할 파일만 복사한 별도 사본에서도 `python -S -m unittest discover -s tests -q`가 통과했습니다. 이때 추가 패키지가 필요한 신경망 3개·LSP 1개는 건너뛰었고, MCP와 하네스·재생 경로는 표준 라이브러리로 검사했습니다.

- **파일 수정:** 4B가 4번의 모델 호출과 read_file/write_file/check_file을 거쳐 JSON의 practice=true를 실제 결과로 확인했습니다. 244개 이벤트를 JSON으로 내보내고 브라우저 본문 반영까지 확인했습니다. 이 기록은 배포 샘플에 포함했습니다.
- **계산과 텐서:** 0.6B가 add_numbers를 요청하고 385를 받아 답한 463개 이벤트를 확인했습니다. 실제 텐서·KV 표본을 포함하며 배포 샘플에 보존했습니다.
- **MCP 비교:** 같은 요청에서 연결 전에는 내장 계산 도구, 연결 후에는 실제 MCP 계산 도구를 사용했습니다. 공개 도구 수가 6개에서 7개로, MCP 전송·수신이 0개에서 6개로 변했습니다. 양쪽 답은 385였지만 연결 전 모델은 “MCP가 없으면 없다고 답하라”는 지시를 놓쳤습니다.
- **LSP 비교:** 연결 전의 구문 검사는 통과했습니다. 모델이 파일을 읽고 미정의 이름을 추측한 것과 별도로, 연결 후에는 실제 언어 서버의 진단을 받았습니다. 공개 도구 6→9개, LSP 전송·수신 0→6개, 모델 호출 3→2회였습니다. 후속 답변은 정규화한 8행·12열을 사용했습니다.
- **생성 중 KV 비교:** 같은 123개 입력 토큰에서 5개 토큰을 생성했습니다. KV를 끄면 forward 입력 누적 625, 켜면 127이었고 출력은 같았습니다. 요청 간 접두부 재사용은 양쪽 모두 끈 별도 실험입니다.
- **집중 비교:** 같은 요청·모델에서 기본은 모델 2회·입력 2,451토큰·12.59초, 집중은 모델 3회·입력 4,242토큰·25.6초였습니다. 집중의 세 번째 실제 요청에 점검 지시가 들어갔습니다. 답변 품질 향상을 입증한 수치는 아닙니다.
- **하위 위임:** 실제 4B 모델이 Explore·Oracle에 두 작업을 전달했습니다. 각 하위는 모델 2회와 파일 읽기 1회, 주 에이전트는 모델 2회와 위임 1회였습니다. 전체 모델 6회·도구 3회·입력 7,537토큰, 계산 차례 대기 누적 약 9,421ms를 기록했습니다. 하위 보고와 상태가 실제 주 모델의 다음 입력에 포함됐습니다. 704개 이벤트를 익명화 샘플에 보존했습니다.
- **위임 비교:** 같은 일반 요약 요청에서 단일 모드는 모델 2회·입력 2,451토큰·13.53초, 위임 모드는 모델이 하위 한 개를 선택해 전체 모델 4회·입력 5,199토큰·22.92초였습니다. 모드 선택이 하위 두 개나 속도 향상을 강제하지 않는다는 사실도 확인했습니다.
- **실제 요약·재사용:** 공개 실습 대화 2,488자를 실제 4B 모델이 73자로 요약했습니다. 원문은 보존하고 요약·최근 원문으로 답변했습니다. 이 실행의 요약+답변은 입력 2,226토큰·출력 81토큰이었고 다음 요청은 추가 요약 없이 입력 441토큰·출력 13토큰으로 응답했습니다. 두 실제 기록과 당시 원문 저장소를 배포 샘플로 보존했습니다.
- **화면:** 실제 단계 정지·다음·계속, 원문/코드 이동, 편집/복원, 저장 기록 재생, 오류 대조, 반응형 화면을 브라우저에서 확인했습니다.

A 다음 B를 한 번 실행한 시간 차이는 순서·캐시·워밍업·관찰 비용의 영향을 받습니다. MCP나 LSP를 붙이면 항상 빨라지거나 정확해진다고 주장하지 않습니다.

## 반복 응답 중단

같은 미검증 응답·미충족 조건·도구 호출 수가 세 번 연속 반복되면 `validation.repeat`를 남기고 실패로 중단합니다. 새로운 도구 호출과 다른 응답에서는 연속 횟수가 초기화되는지 검사합니다. 실제 4B의 동일 첫 입력 비교에서 호출 8→3회, 누적 입력 9,736→2,721토큰으로 바뀌었고 양쪽 모두 필수 도구 미호출로 실패했습니다. 기록과 범위는 [유사 제품 비교](COMPARISON.md)에 있습니다.

## 의존성·모델 파일 확인

Transformers를 4.57.3에서 5.22.2로 갱신했습니다. 실제 고정 Qwen3-0.6B의 토큰 생성·attention 기록과 두 번째 호출의 접두부 KV 재사용을 확인했습니다(배포 샘플 **토큰·실제 텐서·KV**의 `reference.cache.select` 기록: 1회차 995토큰 중 재사용 0, 2회차 1,061토큰 중 991 위치 재사용). 작은 실제 신경망 테스트는 KV 사용/재계산, 접두부 crop, 중지와 관찰 시간의 표시 의미를 검사합니다.

`pip-audit`로 현재 Windows 환경의 50개 항목을 검사했습니다. 검사 가능한 49개에서는 알려진 취약점을 찾지 못했고, `torch==2.8.0+cpu`는 로컬 빌드 태그 때문에 PyPI 기준으로 감사되지 않아 제외됐습니다. 공식 권고 데이터베이스(GitHub Advisory Database·OSV, 2026-11-08 확인)를 따로 대조하면 torch 2.8.0은 [CVE-2026-24747](https://github.com/advisories/GHSA-63cw-57p8-fm3p)(High, `torch.load(..., weights_only=True)`로 조작된 체크포인트를 열 때 메모리 손상, 2.10.0에서 수정), [CVE-2026-4538](https://osv.dev/vulnerability/PYSEC-2026-139)(pt2 로딩 핸들러의 안전하지 않은 역직렬화, 로컬 접근, 2.10.0까지 영향)과 2.9.0에서 수정된 서비스 거부 계열([CVE-2025-55551](https://osv.dev/vulnerability/PYSEC-2025-203) 등)의 영향 버전입니다. 이 앱은 `torch.load`·pt2 로딩·해당 선형대수 연산을 호출하지 않고 크기·SHA256을 고정한 safetensors만 읽지만, 그것이 영향 없음의 보증은 아닙니다. transformers 5.22.2와 python-lsp-server 1.15.0은 같은 날짜 기준으로 미해결 공개 권고가 없었습니다. 이는 모든 의존성의 안전 보증이 아닙니다. 이전 버전 관련 권고의 예는 [LightGlue 설정 로딩](https://github.com/advisories/GHSA-fgcw-684q-jj6r)입니다.

가중치·tokenizer·설정 파일의 크기와 SHA256을 고정 snapshot과 대조합니다. 다운로드뿐 아니라 Python 모델 로드 직전에도 검사하며, 불일치하면 모델을 불러오지 않습니다.

## 알려진 제한

- 요약은 완료한 대화를 다음 요청 전에 처리합니다. 현재 도구 루프의 중간 컨텍스트 초과 자동 관리나 모든 사실의 의미 보존 검증은 포함하지 않습니다.
- 실제 수치도 선택한 레이어·head·위치·차원의 표본입니다. 전체 텐서·모든 코드 줄·숨겨진 사고를 기록하는 제품이 아닙니다.
- MCP는 단일 stdio 프로필, 명시적 도구 허용 목록, 단순 스칼라 schema와 complete 결과만 지원합니다. 모든 버전·서버의 적합성 검증이나 HTTP/OAuth는 포함하지 않습니다.
- LSP는 Python의 진단·문서 심볼·정의를 지원합니다. 외부 서버 내부의 모든 연산을 추적하지는 않습니다.
- 지적 재포함은 완료한 대화의 같은 요청 해시에 대한 명시적 정책입니다. 모델 훈련이 아니며, 포함된 지적을 모델이 항상 따르지는 않습니다.
